# Per-model context and compact catalogue

Continues the existing Part 2 work without replacing inference, model storage or GPU runtimes. APK 10515/AppImage from e14fa1d predate these changes; no replacement packages were built here.

- Compact catalogue rows show file size, architecture, actual GGUF block count, installation/loading status and a primary Download/Use/Load action. Secondary verification/deletion/source/license information remains in Details. Selection, disk verification and loaded state remain separate.
- Existing GGUF parsing now preserves architecture-specific `context_length` and reads `block_count` (not a name/size estimate). Browser/import inspection uses bounded 64 KiB windows and skips tokenizer arrays. Native-file inspection consumes/discards a stream and cancels before tensors rather than materializing response.blob(). Existing desktop-folder parsing remains bounded to its 16 MiB metadata window. Missing/invalid layer counts show Unknown.
- Legacy descriptor `maxContext` stays a safe runtime default for compatibility. The declared model maximum, saved context preference and backend-confirmed applied context are independent values. Per-model preferences/metadata use new localStorage namespaces keyed by GGUF checksum; ordinary reimport restores the same settings. Read-only desktop-folder identities include path identity and file stat identity, preventing reuse after ordinary file replacement.
- A logarithmic slider and exact integer input are synchronized. Valid bounds combine the parsed model limit and the backend's signed-integer context argument bound; they do not promise sufficient memory. If the header is unavailable, retain a conservative 2048 configuration bound until inspection. There is no universal 131072 model cap.
- Automatic mode normally chooses at most 2048, reducing to 512 under conservative available-memory pressure. It never chooses a model's declared maximum or treats all RAM as allocatable. Without reliable memory information it explicitly uses the conservative default. KV-memory feasibility depends on architecture and still needs device testing.
- Save validates before writing, joins model shutdown and applies on the next explicit load. Foreground generation/transfers reject changes with model-busy. Invalid values are not saved. Manual settings are never silently reduced; previous settings remain available for recovery after allocation failure.
- Native CPU/CUDA/Vulkan receive the setting as --ctx-size through the existing process launcher. WASM receives n_ctx. Capacity is read from native /props or startup n_ctx_per_seq/n_ctx logs, or WASM getLoadedContextInfo().n_ctx. Missing confirmation stays Unknown; differing applied values are visible. Last-request usage comes only from backend token usage, not characters or estimates. Existing bridge buffering means usage appears after completion, not as invented live telemetry.
- GPU selection/fallback is unchanged. Total GGUF blocks, requested GPU limit and confirmed GPU offload are labelled separately; device discovery/loading alone never confirms inference.

Validation: TypeScript, directly related GGUF/context/storage and native/folder tests, two JVM context tests (also compiling the Android wrapper), and three browser regressions covering context/UI, installation states and imports. Existing long status/action assertions were updated to the specified short labels and secondary Details location; receipt, partial-transfer, invalid-file and preservation assertions remain. JVM checks use isolated synthetic model-free metadata, not an application package or inference fixture.

Manual acceptance remains: real POCO WebView/native context loads, larger-context allocation/failure/revert, data preservation, and CachyOS CPU/CUDA/Vulkan applied capacities/offload. No real device/GPU inference, APK/AppImage build, dependency update, release or merge is claimed.
