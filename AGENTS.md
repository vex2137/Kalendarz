# Zasady oszczędnej pracy

## Eksploracja

- Sprawdzaj tylko pliki związane z aktualnym zadaniem.
- Nie skanuj całego repozytorium bez uzasadnienia.
- Nie odczytuj ponownie plików, których zawartość już znasz, jeśli się nie zmieniły.
- Ograniczaj wyniki komend i logów do niezbędnych informacji.

## Implementacja

- Wprowadzaj najmniejsze kompletne zmiany rozwiązujące problem.
- Nie wykonuj niezleconego refaktoringu ani dodatkowych funkcji.
- Nie naprawiaj niezwiązanych problemów bez zgody użytkownika.
- Nie przebudowuj działającego kodu bez konkretnego powodu.

## Testowanie

- Nie uruchamiaj testów po każdej edycji.
- Najpierw zakończ wszystkie powiązane zmiany, a potem wykonaj najwęższą adekwatną weryfikację.
- Nie uruchamiaj pełnej baterii testów, lintowania ani kompilacji wszystkich platform po drobnych zmianach.
- Szersze testy wykonuj tylko wtedy, gdy uzasadnia je ryzyko lub zakres zmian.
- Nie powtarzaj udanych testów, jeśli kod i warunki się nie zmieniły.
- Po niepowodzeniu przeanalizuj konkretny błąd przed następną próbą.
- Nie powtarzaj identycznej komendy po identycznym błędzie bez uzasadnienia.
- Nie deklaruj sukcesu testów, których faktycznie nie wykonano.

## Narzędzia i limit

- Nie uruchamiaj dodatkowych agentów, równoległych analiz ani długich diagnostyk bez wyraźnej korzyści.
- Unikaj wielokrotnego analizowania tego samego problemu.
- Nie generuj długich raportów pośrednich.
- Jeśli zadanie jest duże, podziel je na logiczne etapy i realizuj tylko zakres niezbędny do bieżącego celu.
- Po spełnieniu kryteriów zadania zakończ pracę.

## Zakończenie

Podawaj zwięzły raport: co zmieniono, jakie testy rzeczywiście wykonano i jaki był ich wynik oraz jakie problemy pozostały.

## Language for updates

- Write future changelogs, release notes, and GitHub update descriptions in English.
- Keep application features and assistant commands available in English, Polish, Russian, and German.
- Default new installations to English; preserve an existing explicit language choice.
